# Emergency alert sound

Install **Closeby 0.1.2** (`dist/android/Closeby-0.1.2.apk`) on recipients' Android phones. This version includes the audio module and an original ringtone bundled with the app. Existing space membership and emergency recipient choices stay in effect.

When an incoming emergency alert appears while Closeby is open, the recipient hears a repeating ring and the existing phone vibration. Sending an alert does not ring the sender's own phone. Pending, unconfirmed sends do not trigger sound. Keep the phone's sound volume audible; the app does not raise system volume or change Do Not Disturb settings. iOS silent mode remains respected.

Tap the emergency banner to open it, or dismiss it with its close button, to stop the ring. Playback also stops after 30 seconds, when Closeby leaves the foreground, when the account or space changes, or when the screen unmounts. Dismissed alerts remain in Safety history. An unacknowledged alert may ring again when the app returns to the foreground. Browser autoplay restrictions or a playback failure show **Retry alert sound**; that button starts playback from a direct user interaction.

This adds sound to the existing in-app emergency delivery. APKs through 0.1.4 do not implement background push delivery. Version 0.1.5 includes native push registration and an Android notification sound, with trusted server activation still pending; see [phone notifications](PHONE_NOTIFICATIONS.md). Building or installing that APK alone does not activate hosted emergency delivery. It does not call emergency services.

The bundled `assets/sounds/emergency-ring.wav` is generated by `python scripts/generate-emergency-ring.py`. Native playback uses [Expo Audio for SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/audio/); browser playback uses an HTML audio element. No microphone permission is requested to play a ring.

Run `node --test tests/emergency-ring.cjs` for repeat playback, timeout, late loading, playback failure, retry, account changes, and cleanup checks. Run `node tests/emergency-ring-browser.cjs` for real decoding and playback using Chrome with muted output; it confirms the asset has audible samples, loops, stops, and can play again. Physical-phone volume, output routing, silent-mode, and Do Not Disturb behavior still require device checks.

`tests/emergency-alert-ui.cjs` runs against local Auth/Firestore emulators and a `--dev` web export using the `demo-closeby` configuration in `.verification/emergency-ring-web-demo`. It sends emergencies between separate local accounts, verifies real recipient playback while the sender stays silent, stops on dismiss/open, and checks that acknowledged alerts stay silent after reopening. All of those checks passed on October 16, 2026, with Chrome output muted during testing.
